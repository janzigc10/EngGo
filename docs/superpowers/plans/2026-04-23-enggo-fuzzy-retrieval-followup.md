# EngGo Fuzzy Retrieval Follow-Up Plan

> 状态：active（2026-04-23 session 已确认并开始执行，不替代 2026-04-21 的已完成 MVP plan）

## 背景

当前版本已经把“低置信度不硬猜”的检索闸门收紧，也验证了聊天主链路、收藏流和基础对比问法是通的。

但用户进一步明确了产品核心价值：不是“标准查词 + 标准答案”，而是更强的模糊检索能力，尤其包括：

- `re+con 的词根有什么词`
- `resent 和 recent 那么像的词要例举出来并且区分`
- `跟 recent 很像的词有哪些`
- `容易把 recent 看错成什么`

当前实现还没有真正支持这类能力。现在的 fuzzy retrieval 仍以“单个英文词的稳定候选选择”为主，更接近收紧后的问答器，而不是“形近词簇 / 片段 / 词根”的模糊联想检索器。

## 本轮 follow-up 的目标

先补上“形近词簇检索 + 区分”这条能力链路，再决定是否做大规模扩库。

原则：

- 不先盲目扩词库
- 先把检索模式做对，再用更大数据量压测
- 第一优先级是形近词簇（shape-neighbor）检索
- 第二优先级才是词根 / 碎片（fragment/root）检索

## 用户想要的效果

### 1. 形近词簇检索

用户输入这类问题时，系统应该返回一组相近词，并说明差别，而不是只挑一个“最稳主答案”：

- `recent 和 resent 的区别`
- `和 recent 很像的词有哪些`
- `容易把 recent 看成什么`
- `resent recent 这组怎么分`

### 2. 词根 / 片段检索

用户输入词根、前后缀、碎片或残缺记忆时，系统应该能返回候选词群，而不是直接 `no_match`：

- `re+con 的词根有什么词`
- `con 开头、re 相关的词`
- `re...ct 这种词`

## 为什么先做形近词簇，不先扩库

- 它最贴近用户真实“看错 / 记混 / 拼歪”的痛点
- 它比普通查词更能体现 EngGo 的差异化价值
- 它会逼着 retrieval 从“单主答案模式”升级为“候选簇 + 区分模式”
- 如果在现有模式下直接扩库，更可能放大误召回、误分组和 `no_match`

## 拟定执行顺序

- [x] Step 1: 先写形近词簇检索的失败测试

首批锁定的代表 case：

- `recent 和 resent 的区别`
- `跟 recent 很像的词有哪些`
- `容易把 recent 看错成什么`
- `adapt 和 adopt 的区别`
- `quiet 和 quite 的区别`

预期方向：

- 返回多个候选词，而不是只保留一个 main answer
- 能解释“为什么会混”
- 能给出最核心的区分点

- [ ] Step 2: 明确 retrieval 新模式与返回结构

建议新增一类检索模式，暂名：

- `shape_neighbor_search`

需要明确：

- 何时触发这类模式
- 它和 `direct_compare` / `fuzzy_recall` 的边界
- 返回结构是否需要新增“相近词簇”字段，避免强塞进现有 `mainAnswer/confusionBoundary`

- [ ] Step 3: 补最小数据模型与 seed 数据

至少补一层“形近关系”数据，而不只依赖 trigram 相似度：

- 哪些词互为形近邻居
- 为什么容易混
- 最关键的区分点
- 是否属于同一考试范围

首批建议先做小样本：

- `recent / resent`
- `adapt / adopt`
- `quite / quiet`
- `affect / effect`

- [ ] Step 4: 实现 retrieval 侧的形近词簇召回

目标：

- 遇到“像 recent 的词”这类输入时，不再只做单候选稳定选择
- 优先返回一个形近词簇
- 若命中显式人工关系，优先使用人工关系
- trigram / word_similarity 作为补充召回，而不是唯一真相源

- [ ] Step 5: 接入回答编排层与前端展示

回答节奏建议：

- 先点名这组最容易混的词
- 再按词逐个区分
- 再补一句考试范围提醒

前端不要退化成纯搜索列表，但应允许一条回答里自然展示多个形近候选。

- [ ] Step 6: 验证形近词簇能力后，再评估扩库压测

形近词簇稳定后，再进入下一轮：

- 扩到 300 ~ 500 词条
- 加入更多高混淆词族
- 跑 retrieval-only 和 chat-level 两套评测
- 观察误召回、漏召回、no-match 准确率和延迟

## Deferred

以下内容先不在下一 session 第一刀里做：

- 大规模词库扩充
- 词根 / 碎片检索的完整实现
- 广泛 typo 容错策略
- 更复杂的开放域联想问法

其中“词根 / 碎片检索”是明确想做的方向，但建议排在形近词簇之后。
