# Vocabulary Learning First Direction

## 背景

EngGo 前几轮已经把聊天式英语学习的核心骨架推进到 V3：普通查词、易混词辨析、形近/词族/中译英召回、短期上下文追问、候选内语境选择和有边界聊天兜底都已经具备雏形。

但继续沿着“大模型多轮对话能力”深挖，会进入高消耗、低确定性的调试循环：发现一个自然问法，再用代码或 prompt 补一个分支，用户换一种表达后又出现新的断点。这不适合作为下一阶段主线。

因此当前方向调整为：先把 EngGo 从“聊天能力调试项目”收回到“词汇学习产品”。

## 新方向

EngGo 的下一阶段定位是：

**词汇学习主流程 + AI 辅助入口。**

聊天仍然存在，但不再作为近期唯一主线。它负责帮助用户查词、辨析、召回易混词，并把有价值的词沉淀到学习资产里；真正的产品感要从词汇学习闭环里长出来。

近期优先级从高到低：

1. 本地生词本和复习状态。
2. 简单、可用、可验证的背词/复习流程。
3. 收藏词的整理、筛选和学习入口。
4. 聊天生成结果到学习资产的稳定沉淀。
5. 仅在边界明确时补充 AI 辅助能力。

## 暂停深入的方向

以下能力先进入维护或后续阶段，不作为下一阶段主线：

- 不继续扩展自然语言问法的 `if` / regex 补丁。
- 不继续深挖开放式多轮聊天。
- 不做长期个人记忆。
- 不做多主题并行上下文。
- 不做 Agent 式自动规划。
- 不做账号、云同步或跨设备状态。
- 不为了让模型“事事有回应”而扩大产品边界。

如果后续确实要继续打磨模型层，应单独开新设计，例如 bounded semantic router，而不是在现有 resolver 里零散补分支。

## 下一阶段产品边界

下一刀应尽量不依赖模型，也不改 `/api/chat`，除非是修阻塞 bug。

建议的第一阶段是 **Wordbook Review V1**：

- 从现有本地收藏数据出发。
- 给每个收藏词增加学习状态，例如未学、复习中、已掌握。
- 提供一个简单复习模式：先看英文，再翻开释义，最后标记记住或没记住。
- 状态保存在本地，不引入 DB schema。
- 不做复杂间隔重复算法，只记录最基础的复习结果和时间。
- 不把复习页做成第二个聊天入口。

## 产品原则

1. **先让学习闭环动起来。** 用户能收藏、看到、复习、标记状态，比继续优化少数聊天问法更重要。
2. **AI 是辅助，不是主舞台的全部。** 模型可以帮助解释、辨析和生成学习材料，但产品不能只靠模型临场发挥。
3. **功能要可验收。** 下一阶段每个能力都应该能用本地状态、组件测试或 smoke 验证，不依赖主观感受。
4. **边界比聪明重要。** 对于不确定的学习意图，宁可保守、澄清或留到后续，不继续打地鼠式补问法。
5. **先做本地单机闭环。** 在没有稳定学习体验前，不做账号体系、云同步和复杂学习计划。

## 与既有设计的关系

- `2026-05-24-conversational-learning-context-design.md` 仍然有效，但进入维护状态；短期上下文只保证已完成能力不回归。
- `2026-05-16-collection-organizer-design.md` 是下一阶段的直接基础，但需要从“收藏整理”推进到“复习状态和复习动作”。
- ECDICT-first 和 optional structured overlay 的词库方向不变。
- 当前 V3 的 bounded chat fallback 保留，但不再把“正常人话都有回应”作为近期继续扩张目标。

## 成功标准

下一阶段成功不以“模型更像 NotebookLM”衡量，而以用户能否完成一个小学习闭环衡量：

1. 用户从聊天或已有收藏中获得一组词。
2. 用户能在生词本里看到这些词。
3. 用户能进入复习。
4. 用户能标记掌握状态。
5. 用户下次回来能看到状态仍然存在。

做到这一步，EngGo 才从“会回答的 demo”变成“能持续学习的产品雏形”。
