# Answer Policy v1 Spec

Date: 2026-05-01

## Summary

EngGo 不能继续做成“没命中词库就不回答”的检索机器人，也不能退化成普通大模型聊天壳。

新的产品原则是：

> 先像大模型一样自然接住问题，再像备考老师一样用考试范围帮用户收束学习决策。

RAG 的核心价值不是让模型更会解释英语，而是帮用户在浩瀚英文词汇里缩小范围：当前阶段什么值得背、什么只需了解、什么可以暂时不学。

因此 Answer Policy v1 的目标是从 `retrieval-first` 调整为 `scope-first`：

- 范围证据优先，但不把范围证据当成封口条件。
- 没有命中当前小词库时，可以回答合理的英语学习问题，但不能假装已经命中考试词库。
- no-match 只作为最后兜底，用于输入过于模糊、乱码、无法判断学习对象的场景。

## Problem

当前系统的前台体验太像规则锁死：

- `你好` 会被当成查词失败，返回 no-match。
- `complex 和 complicate 是一个意思吗` 这类常见英语辨析，如果当前 `real-smoke` 小词库没收录，也会被 no-match 拦住。
- 用户第一次打开产品时，会自然把它当聊天式英语助手；如果连基本交流和常见解释都接不住，会显得“不智能”。

但 EngGo 不能简单放开成普通大模型，因为产品价值来自考试范围和学习收束：

- 用户是为了应试，不是为了泛泛学英语。
- 用户需要知道哪些词当前阶段需要背，哪些不必投入时间。
- 已命中的词库、易混组、碎片召回仍然应该提供最可靠的 grounding、收藏和后续复习入口。

所以要修的不是“规则太多”，而是“规则直接挡在用户面前”。

## Product Principle

### 1. 范围优先，不范围专制

当前考试范围是优先级系统，不是封口系统。

- 命中范围：明确告诉用户这是当前阶段应优先掌握的内容。
- 未命中当前小词库：可以给通用解释，但要避免声称它来自当前考试词库。
- 确认范围外：可以轻量解释，但应提示“当前阶段不优先”。

### 2. 先接住，再收束

用户的问题应该先被自然接住。EngGo 的老师感来自：

- 先回答用户眼前的问题。
- 再帮用户判断学习优先级。
- 最后给出可继续的学习动作。

### 3. no-match 降级为兜底

no-match 不应该是默认失败页。

只在以下场景使用：

- 输入太模糊，无法判断学习对象。
- 拼写/碎片置信度过低，强行猜测会误导。
- 语义词根组合还没有产品定义，例如当前阶段的 `re+con`。

### 4. 不伪造范围证据

通用回答可以存在，但必须和 grounded 回答区分。

EngGo 不能说：

- “这是 CET-6 高频词”，除非有范围证据。
- “当前考试范围内没有”，除非数据源已经完整到能支持这个判断。

在 `real-smoke` 仍是小切片时，更准确的说法是“当前词库还没稳定收录/定位到”。

## Answer Modes

### A. Greeting / Entry Answer

用于 `你好`、`hi`、`hello` 等入口型输入。

行为：

- 不走检索。
- 不调用考试词库。
- 直接自然回应，并引导用户输入词义、拼写片段、易混词或考试范围问题。

示例：

> 你好。你可以直接问一个单词、两个易混词，或者给我一个中文意思，我会先按当前考试范围帮你缩小。

不显示：

- 命中状态
- 收藏工具
- no-match 卡片

### B. Grounded Learning Answer

用于当前已经支持的稳定命中场景：

- 普通查词命中
- 易混词组命中
- 形近词命中
- 中文表达召回命中
- 词根/后缀/碎片召回命中

行为：

- 继续使用 retrieval -> grounding -> provider。
- 显示命中状态、下一步和收藏工具。
- 明确体现当前考试范围。

这是 EngGo 与普通大模型的核心差异区。

### C. General Learning Answer

用于没命中当前词库，但用户问题本身明确、合理、属于英语学习的场景。

典型例子：

- `complex 和 complicate 是一个意思吗`
- `available 怎么用`
- `这个词能不能造个句`
- `economic 和 economical 有什么区别`，当两者还没稳定入库时

行为：

- 可以调用大模型给通用解释。
- 不显示“命中状态”。
- 不显示收藏工具，除非后续支持“加入我的学习范围”。
- 可以轻提示数据边界。

推荐语气：

> 不是一个意思。先按通用英语理解：complex 多表示“复杂的”，complicate 是“使复杂化”。这条我当前还没有绑定到你的考试词库命中结果，所以先不标成当前范围优先项。

这类回答的目标是让产品显得聪明、自然，但不乱认账。

### D. Clarify Answer

用于用户明显想学英语，但输入不够明确。

例子：

- `这个 con 是什么意思`
- `re+con 有哪些`
- `有个 c 开头很像的词`
- 只给半截且候选过多

行为：

- 不急着 no-match。
- 用一两句话追问，帮助用户缩小。
- 可以给可选方向，例如“你是想问前缀、词根，还是某个单词？”

示例：

> 你这里可能是在问前缀，也可能是在问某个词形片段。你可以再给我一个完整单词，或者说“con 开头的词有哪些”，我再按当前考试范围帮你缩小。

### E. No-Match Fallback

最后兜底。

用于：

- 低置信拼写无法定位。
- 规则上明确不支持的词根理论组合。
- 无法判断是否为英语学习问题。

行为：

- 保留克制，不硬猜。
- 文案要避免把“当前小词库没命中”说成“考试范围不存在”。
- 给出下一步输入建议。

## UI Rules

不同回答身份需要在界面上区分：

- Grounded answer：显示 `命中状态`、`下一步`、收藏工具。
- General answer：只显示自然回答和轻提示，不显示命中状态。
- Greeting：像入口助手，不显示 no-match 卡片。
- Clarify：用追问卡，不显示收藏工具。
- No-match：显示兜底说明，但文案要更谨慎。

这能避免用户误以为所有回答都来自考试词库，也避免通用回答看起来像系统失败。

## Data Boundary

当前 `real-smoke` 是 source-backed 小切片，不是完整考试词库。

因此 Answer Policy v1 必须区分：

- `in_scope_hit`：当前词库已命中当前范围。
- `known_out_of_scope`：未来完整词库或范围源能确认不属于当前范围。
- `not_in_current_dataset`：当前小词库暂未收录，不能据此判断考试范围外。

在完整词库前，文案应优先使用“当前词库暂未稳定收录”，而不是“当前考试范围内没有”。

## Non-Goals

- 不做完整 Agent 框架。
- 不做学习计划、复习队列、长期记忆。
- 不一次性扩全量词库。
- 不让通用回答获得收藏和命中状态。
- 不把 general answer 当成考试范围证据。
- 不改变已有 grounded 场景的保守性。

## Acceptance Criteria

- `你好` 返回自然入口回答，不显示 no-match。
- `complex 和 complicate 是一个意思吗` 在未命中当前词库时仍能得到通用英语解释。
- general answer 不显示 `命中状态` 和收藏工具。
- 已命中的 `tion 结尾的词有哪些`、`access assess excess 怎么区分` 继续走 grounded answer。
- `re+con 的词根有什么词` 这类未定义词根组合仍保持 clarify 或 no-match，不硬编词族。
- no-match 文案不再暗示当前小词库等于完整考试范围。
